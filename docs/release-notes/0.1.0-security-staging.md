# Release notes: staging and authorization/security evidence

## Issue

Closes #97.

## Summary

This release adds production-like staging configuration, authorization matrix
evidence, rate limiting, security scanning in CI, and runbooks for migration
and incident response.

## What's new

### Infrastructure and staging

- Added `infra/compose.staging.yaml`, a hardened override that:
  - Requires OIDC issuer and JWKS URL.
  - Explicitly clears `TRADEFLOW_AUTH_TEST_SECRET` so the application rejects
    test-token signing in staging.
  - Enables telemetry and rate limiting.
- Added `docs/runbooks/staging-deployment.md` with deployment and verification
  steps.

### Authorization and security

- Added `docs/security/authorization-matrix.md` documenting capabilities,
  operational scope, approval authority limits, and Maker-Checker controls.
- Added contract tests in `apps/api/tests/test_authorization_matrix_contract.py`
  verifying:
  - Administrator status does not escalate to business approvals.
  - Approver without an Approval Authority row is denied.
  - Cross-branch Approval Authority is denied.
  - Approval exceeding the amount limit is denied.
  - Valid capability + scope + limit succeeds.

### Rate and session controls

- Added `RateLimitMiddleware` with a sliding-window, per-identity rate limiter.
- Health endpoints (`/health/live`, `/health/ready`) are exempt.
- Authenticated requests are bucketed by bearer token; unauthenticated requests
  are bucketed by IP.
- Returns `429 rate_limit_exceeded` with a `Retry-After` header.
- Added contract tests in `apps/api/tests/test_rate_limit_contract.py`.

### CI/CD hardening

- Added `.github/workflows/security.yml` with:
  - Secret scan blocking test secrets in staging/production files.
  - High-entropy pattern scan for common secret shapes.
  - Dependency review on pull requests.
  - Log scan to prevent credential material in repository logs.
  - SBOM generation evidence.

### Observability

- Added `TRADEFLOW_OTLP_ENDPOINT` and `TRADEFLOW_WORKER_OTLP_ENDPOINT` settings
  for centralized trace export.

### Runbooks

- `docs/runbooks/staging-deployment.md`
- `docs/runbooks/migration-rollback.md`
- `docs/runbooks/security-incident-response.md`

## Migration impact

No database schema changes were required for this slice.
